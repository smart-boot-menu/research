# Debian 13.8.0 arm64 netinst, one QEMU boot

Date: 2026-11-26. One run. This is a boot log, not a benchmark.

Image: `debian-13.8.0-arm64-netinst.iso`, 737456128 bytes, SHA-256 `f4e05f67b5c74e3ff7b24c2a8f889960f9eb31fe0c1ac8513d27d5656958b6b3`, matching the arm64 `SHA256SUMS` retrieved the same day.

Host firmware for the guest was `/opt/homebrew/share/qemu/edk2-aarch64-code.fd` (67108864 bytes, dated Oct 28 in the local Homebrew share) and a copy of `edk2-arm-vars.fd`. The machine type was `virt` with HVF. No host disk was attached. The guest is generic AArch64 UEFI, not Apple Silicon.

Command:

```
qemu-system-aarch64 -machine virt,accel=hvf -cpu host -m 2048 -smp 2 \
  -drive if=pflash,format=raw,readonly=on,file=/opt/homebrew/share/qemu/edk2-aarch64-code.fd \
  -drive if=pflash,format=raw,file=build/efivars.fd \
  -cdrom build/cache/debian-13.8.0-arm64-netinst.iso \
  -boot order=d -display none -serial file:build/boot-serial.log \
  -monitor none -no-reboot
```

The wrapper sent SIGTERM after 75.0 seconds. QEMU reported termination on signal 15. The serial file was 6769 bytes.

Firmware and bootloader text in that file:

- `UEFI firmware (version edk2-stable202408-prebuilt.qemu.org built at 16:28:50 on Sep 12 2024)`
- `Image type X64 can't be loaded on AARCH64 UEFI system.`
- `BdsDxe: loading Boot0001 "UEFI Misc Device"`
- `GNU GRUB  version 2.12-9+deb13u4`
- menu text including `*Install` and `Graphical install`

The X64 image error is the firmware skipping a non-AArch64 image. GRUB still started and showed the Debian installer menu. The process was stopped at that menu. No operating system was installed.
